# LIVE-36146 — [HEDERA] Persist hederaResources via buildAccountShape and accountRawAssign

- Epic: LIVE-29812 · Status: TO DO · Estimate proposed: 3 SP
- https://ledgerhq.atlassian.net/browse/LIVE-36146

## Description

Keep Hedera's account-level state alive on the generic path.

Hedera persists three fields the shared account shape cannot express: the maximum number of automatic
token associations, whether automatic association is enabled, and the delegation. The legacy bridge
serializes them today. On the generic path they need the family account-shape hook to produce them
and the raw-assign hook to survive the save/restore round trip. Without both, the fields are
permanently undefined.

**Do not try to set `freshAddress` from the account-shape hook** — its type forbids writing any field
of `Account`, so it cannot. The account id arrives from the account-discovery scan instead.

This is narrower than the same work on other families: Hedera's resources carry no public key (the
device key lives in `seedIdentifier`), so there is no public-key resolver to repair and no change in
the meaning of `xpub`.

`families/tezos` is the reference — the only family with the full set of four family-layer files.

## Acceptance criteria

- [ ] The three fields are populated after a sync on the generic path
- [ ] They survive a save/restore round trip
- [ ] The values match what the legacy bridge produces for the same account
- [ ] Existing serialization tests still pass

## Code notes (verified 2026-08-19)

- Source of the three fields today:
  `libs/coin-modules/coin-hedera/src/bridge/synchronisation.ts:142-146`

  ```ts
  hederaResources: {
    maxAutomaticTokenAssociations: mirrorAccount.max_automatic_token_associations,
    isAutoTokenAssociationEnabled: mirrorAccount.max_automatic_token_associations === -1,
    delegation,   // { nodeId, delegated, pendingReward } | null
  }
  ```

- `BridgeApi.buildAccountShape(address, accountInfo?)` returns `FamilyAccountShape =
  Record<string, unknown> & Partial<Record<keyof Account, never>>` — the type literally forbids any
  `Account` key, which is why `freshAddress` cannot be set there
  (`libs/ledger-wallet-framework/src/api/types.ts`).
- Raw-assign reference: `libs/ledger-live-common/src/families/tezos/accountRawAssign.ts` — a two-line
  default export of `{ assignFromAccountRaw, assignToAccountRaw }` pulled from the family's
  `serialization.ts`. Hedera already has `libs/coin-modules/coin-hedera/src/bridge/serialization.ts`.
- Registered through `loadAccountRawAssign` in
  `libs/ledger-live-common/src/coin-modules/loaders.ts` (see the tezos entry, line ~383).
- `delegation.delegated` / `pendingReward` are `BigNumber` — they must be stringified in
  `assignToAccountRaw` and revived in `assignFromAccountRaw`.
