# LIVE-36154 — [HEDERA] Register loader hooks and enable the generic adapter family flag

- Epic: LIVE-29812 · Status: TO DO · Estimate proposed: 3 SP
- https://ledgerhq.atlassian.net/browse/LIVE-36154

## Description

Turn the family on. **This is the merge point and the point of no return:** the allowlist resolves per
family, so `hedera` and `hedera_testnet` move together and there is no staged rollout.

### 1. Loader hooks

Hedera's loader entry has three of the seven hooks. Add the four it lacks: the local api, the signer,
the bridge api and the account raw assign. Registration is **central**, in the coin-modules loader
array — not in per-app setup files, whatever the integration guide says. Tezos's entry is the model.

### 2. Default transaction

Register `hedera` in the shared default-transaction switch with a zero nonce. This is required
regardless, because that switch throws on an unknown family. It is also what keeps the signing path
away from `getNextSequence`, which Hedera has no answer for: the chain has no nonce or account
sequence, and replay protection comes from the transaction id and its validity window instead. NEAR,
VeChain and Cardano already do exactly this.

**Two consequences to call out in the pull request** so a reviewer does not read them as unfinished
work: `getNextSequence` stays throwing on purpose, and a pending Hedera operation will report a
transaction sequence number of zero — as it already does for those three families.

### 3. The flag

Add `hedera` to the generic coin framework family list.

### 4. Non-regression

Sweep the coin module's api tests for anything still asserting a pre-migration throw or assertion on
a method that now works. That suite pins the old behaviour deliberately, so a green run is not by
itself evidence of readiness.

### Blocked on

The shared-layer change that exposes custom account discovery through the generic currency bridge.
Hedera accounts are found by looking up the device's public key on the mirror node rather than by
walking derivation paths, so adding an account will not work on the generic path until that lands.

> See `../gaps/GAP-A-buildIterateResult.md` — the blocker is ~8 lines and can be unblocked locally.
