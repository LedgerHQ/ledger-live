# LIVE-36151 — [HEDERA] Migrate desktop staking UI to the generic transaction shape

- Epic: LIVE-29812 · Status: TO DO · Estimate proposed: 3 SP
- https://ledgerhq.atlassian.net/browse/LIVE-36151

## Description

Move Ledger Live Desktop's Hedera staking flows off the transaction field they use today.

The flows read and write `transaction.properties.stakingNodeId`. The generic transaction has no
`properties` bag; it carries `valId` for this purpose. Every read and write has to move.

**This is a real UI change, not a configuration line.** Eight files across the four staking flows are
involved — delegation, redelegation, undelegation and claim rewards — and reads and writes are
entangled in the same components, so they move together rather than in separate passes.

Two details worth knowing. One read is a type guard on a number that gates progression through the
flow, so it has to keep working — and `valId` is typed as a string, so settle the conversion at the
boundary. And the redelegation validator step renders the `stakingNodeId` error key, so this work
meets the transaction-status task on that key.

## Acceptance criteria

- [ ] All four staking flows complete on desktop against the generic bridge
- [ ] The selected node id is carried correctly from selection through to the signed transaction
- [ ] The validator step still renders its error and still blocks progression
- [ ] No desktop component reads `transaction.properties` for Hedera
- [ ] Existing desktop tests updated
