# LIVE-36145 — [HEDERA] Add coinModuleApi factory and BridgeApi hooks

- Epic: LIVE-29812 · Status: TO DO · Estimate proposed: 5 SP
- https://ledgerhq.atlassian.net/browse/LIVE-36145

## Description

Add the two remaining family-layer files: `families/hedera/coinModuleApi.ts` and
`families/hedera/bridge/api.ts`.

`coinModuleApi.ts` is the mechanical factory that returns the coin module's API for a currency id.

`bridge/api.ts` is mostly wiring rather than new logic. `getTokenFromAsset` and `getAssetFromToken`
already exist in `coin-hedera` and are simply not exposed. Set staking supported to true —
`getBalance` already returns a populated stake carrying the delegated amount, the pending reward and
an `overstaked` flag, which is exactly what that flag's contract requires.

**One trap worth knowing.** `createApi`'s return type includes `& BridgeApi`, but that intersection is
dead: the framework sources the bridge api from the family loader, never from the coin module's
return value. Anything placed there is unreachable, so every hook belongs in this file.

**Two decisions, already settled — implement them, no investigation needed.**

- **Use the aggregate staking resources, not per-stake positions.** Hedera stakes to a single node id
  and `getBalance` attaches at most one stake, so the positions mode would wrap a single item with
  nothing to group. That mode exists for chains that must preserve each position individually, and
  only Tezos and Celo use it. Leave the positions flag unset.
- **Map the staking node id onto `valId`**, not `valAddress`. Hedera stakes to a node _id_, and the
  generic transaction already carries `valId` for exactly this.

Also settle the optimistic-operation description. It exists so a pending row's type matches what the
following sync produces, which matters here because reward operations are synthesized rather than
fetched from the chain.

## Acceptance criteria

- [ ] `coinModuleApi.ts` exports the currency-id factory and is wired into the loader
- [ ] `bridge/api.ts` exposes the token mappers and declares staking supported
- [ ] Account sync produces the aggregate staking resources, with the positions flag unset
- [ ] The staking node id round-trips through `valId`
- [ ] A pending staking operation's type matches what the following sync produces
- [ ] Unit tests on each hook
