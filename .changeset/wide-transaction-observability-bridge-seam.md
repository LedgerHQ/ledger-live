Add the new `@ledgerhq/transaction-observability` package: the sign/broadcast log-event model, a global observer registry, error and action classification, and the Segment mapping. It lives in a dedicated `libs/*` package rather than the deprecated `@ledgerhq/live-common` (which no longer accepts new top-level modules); `@ledgerhq/live-common`, ledger-live-desktop and ledger-live-mobile consume it.

Add wide transaction (sign + broadcast) observability at the account-bridge seam. `wrapAccountBridge` decorates `signOperation` and `broadcast` and emits a normalized `LogEvent` through a global observer registry (`setTransactionObserver`/`emitTransactionEvent`), covering every route (native send/staking, wallet-api, dApp) and every coin without touching the pure coin modules. The device-action layer adds funnel `started` and sign-prompt `abandoned` signals, and device/transport status errors are classified into a stable `ErrorCategory` (including on-device declines). The delegation target (`validators`) is captured at the sign stage.

Derive an `earnTransactionType` — a normalized action (`delegate`, `undelegate`, `redelegate`, `claimReward`, `compoundReward`, `withdraw`, `approve`, `deposit`, `redeem`) mapped **per coin family** from the family's own wording (`mode`, Solana `model.kind`, TON `payload.type`, or an EVM selector name). The six staking values are `StakingOperation` from `@ledgerhq/coin-module-framework`, with a compile-time guard that fails the build if that vocabulary drifts. The raw family value is kept alongside as `rawTransactionType` for drill-down. A family-agnostic word list could not express this: the same word differs per family (Celo `vote` and Tron `freeze` both start staking; TON `jetton-burn` is an unstake) and Solana's dotted actions were missed entirely.

Add an additive Segment/Mixpanel observer (desktop + mobile) emitting `earn_transaction_completed` / `earn_transaction_failed`, matching the names and property vocabulary the Earn live-app emits so both halves of the funnel join. Events carry `stage` (sign/broadcast), `transaction_type`, `raw_transaction_type`, `input_currency` (ticker) with `network` alongside, `provider` (live-app manifest id), `validators`, and `error_category` + `error_reason` on failure — never a raw error message or signature. Two gates keep the data honest: transactions with no recognised staking/yield action (plain sends, swaps) are not emitted at all, and transactions originating from the Earn live-app are skipped because that app emits these events itself with richer context. The existing Datadog `useBroadcast` path is left untouched, and desktop also registers a dev-only console observer for local verification.
