Same layers — three changes

Same five layers on both sides — we only changed the three in teal. Specs and the raw-Detox escape hatch are identical, so this isn't a rewrite of how tests are written, it's a refinement of the middle. (Verbally set up the context here: mobile is the authoritative suite — 216 specs, in CI; next-gen is a sandbox.)

1 · Element layer

String ids + global functions over raw Detox → a typed handle that owns its match strategy and waits before every action.

e2e/mobile — 83 injected globals


recipientInputId = "recipient-input";

await waitForElementById(this.recipientInputId);
await typeTextById(this.recipientInputId, address);

detox-next-gen


recipient = byId("recipient-input");

// waits, then acts — one call
await this.recipient.replaceText(address);

Win: every action waits first → kills the #1 flake; strategy explicit at definition; native + web symmetric.   Cost: a new lib to learn and own.

Mobile repeats the id and splits wait from act. Next-gen declares the locator once with its strategy, and the wait is baked into .tap()/.fill()/.replaceText(). This is the slide to run the fast-fail demo on.

2 · Cross-page flows

A page method coupled to other pages → pages stay leaves; cross-page orchestration moves to flows/<feature>/.

e2e/mobile — a page reaches into others


// buySell.page.ts (BuySellPage)
async chooseAssetIfNotSelected(account) {
  if (await app.modularDrawer.isFlowEnabled(...))
    await app.modularDrawer.selectAsset(account);
  else
    await app.common.selectAccount(account);
}

detox-next-gen — a flow over pages


// flows/swap/swapFlow.ts — selectSwapCurrency()
await app.swapLiveApp.tapFromSelector();
await app.modularDrawer.chooseAsset(ticker, name);
await app.modularDrawer.selectAccount(name);

Litmus: touches >1 page → flow; one page → page method.   BuySellPage depends on ModularDrawer + CommonPage; in next-gen that orchestration lives in swapFlow, so pages never reference each other.

Concrete files: in mobile, BuySellPage.chooseAssetIfNotSelected (page/trade/buySell.page.ts:70) reaches into two other page objects in one method — app.modularDrawer and app.common. That cross-page knowledge sits inside a page. In next-gen, selectSwapCurrency lives in flows/swap/swapFlow.ts:34 and spans swapLiveApp + modularDrawer; its file comment says it lives there to avoid page→page delegation. Pages stay leaves → no circular deps, each readable alone.

3 · Timeouts

One uniform 60s knob → named speed tiers, fast-by-default, opt up on demand.

e2e/mobile


// applied to ~every wait
const DEFAULT_TIMEOUT = 60000;

detox-next-gen


XS=1s  S=5s  M=60s  L=120s  XL=180s

// default XS; a slow step opts up
async openViaDeeplink(t = TIMEOUTS.M) {}

Win: a failing test fails in ~1s, not 60s — tight loop, fast red signal; the tier names the intent.   Cost: mis-tiering → flake (we hit it twice). A deliberate trade.

Keep this one brief — it's the last topic before the ask. Mobile's 60s is slow-but-safe. Tiers trade that for speed + intent, and ask the author to think about each wait. Be honest about the new failure mode.

Benefits — talking points

BenefitTalking points (proof + rebuttal)
Fewer flakes
  • Every action waits for visibility first — the #1 Detox flake, gone by construction
  • "Mobile waits too" → only if you remember waitForElementById; here it's not optional
Faster signal
  • Default tier 1s vs mobile's uniform 60s — a real failure returns in ~1s
  • "Won't 1s flake?" → slow steps opt up (M/L/XL), named at the call site
Clearer failures
  • Error names the element + strategy, not web element to exist
  • Known error screens report the on-screen text, not a generic timeout
Cleaner to change
  • Pages are leaves; cross-page logic written once in flows/, reused
  • "Mobile has flow-helpers" → but its pages call pages (BuySellPage → 2 pages); here that's impossible
Explicit deps
  • Imports → go-to-definition, autocomplete, knip, safe renames
  • No 83-global global.d.ts to keep in sync; types can't drift
Easier to onboard
  • Specs read as app.*; conventions written (README + docs/ + AGENTS.md)
  • A new dev — or AI — finds a helper because it's imported, not ambient
Q&A armor: each benefit with its proof and the rebuttal to the obvious pushback. You don't have to present it — keep it ready to jump to when a claim gets challenged. Facts to anchor on: waitForElementById is opt-in in mobile; mobile's default is 60s; BuySellPage.chooseAssetIfNotSelected drives two pages; global.d.ts declares 83 globals.

The plan

  • Keep detox-next-gen as a reference + lab — prove patterns here first
  • Add the improvements into e2e/mobile — in-place, incremental

Harvest the lab into the suite we already trust.

detox-next-gen isn't thrown away — it's the reference + lab where these patterns (and the diagnostics win) got validated. We fold the improvements into mobile incrementally: timeouts tiers + failure diagnostics are additive and land now; typed element handles get used on new specs; pages-as-leaves is a convention for new code. This avoids the two-suite maintenance tax and divergence.
