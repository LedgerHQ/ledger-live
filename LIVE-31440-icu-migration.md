# LIVE-31440 — full ICU MessageFormat migration

## Why

i18next's native format (`{{var}}` interpolation + `key_one`/`key_other` suffix plurals)
is not understood by Smartling well enough to expand plural categories: languages like
Russian need `one`/`few`/`many`/`other`, but Smartling can't generate the missing forms
from i18next suffix keys, so today the RU files only ship `_one`/`_other` and plurals are
grammatically wrong.

ICU MessageFormat fixes this: a single key holds all plural logic, and Smartling parses
it natively (`string_format: icu`) and expands the target-language categories. This is the
format already used by `earn-live-app` internally.

## What changed

The whole i18n layer moved to **100% ICU MessageFormat**, matching `earn-live-app`.

### Runtime
- `i18next-icu` (official plugin) + `intl-messageformat` added to both apps.
- Both i18n inits use `.use(new ICU({ parseErrorHandler }))`:
  - global ICU means **all** interpolation is single-brace `{var}` and every plural/select
    is ICU — there is no more `{{var}}`.
  - `parseErrorHandler` defaults `count` to `1` (singular) if a plural key is ever resolved
    without `count`, so a raw ICU template is never shown (mirrors i18next's old behaviour
    where the un-suffixed base key was the singular form).
- `intl-messageformat` / `@formatjs` added to both apps' jest `transformIncludePatterns`.

### Translation files (all 12 locales, both apps)
- `{{var}}` → `{var}`; `{{var, number/date/time}}` → `{var, …}`.
- `key_one`/`key_other`/`_zero`/`_two`/`_few`/`_many` (and the legacy un-suffixed base =
  singular) folded into a single `{count, plural, …}` key. `_zero` → `=0` exact match.
- ICU-significant characters escaped in literal text (`'` → `''`, `{`/`}` → `'{'`/`'}'`).
- `<Trans>` tags (`<0>…</0>`) are preserved — numeric tags are literal to ICU and parsed
  by `<Trans>` afterwards.
- The `smartling` directive block was added to each `en` source:
  ```json
  { "smartling": { "entity_escaping": "false", "string_format": "icu" } }
  ```

### Call-sites
- `stake.noFundsModal.title` used the i18next `list()` formatter (no ICU equivalent). The
  list is now built with `Intl.ListFormat` at the call-site and passed as a string.

## How it was verified

A codemod converted every string in every locale, then a checker compared **old (native
i18next) vs new (ICU)** rendered output for every key, locale and plural category:

- mobile: **67 052 assertions, 0 mismatch**
- desktop: **63 518 assertions, 0 mismatch**

Plus React integration tests (`icuIntegration.test.tsx`, both apps) covering
`useTranslation` and `<Trans>` for interpolation, plural (incl. Russian few/many), `=0`,
`select`, missing-count fallback and embedded tags; and the previously-failing app tests
now pass.

## Notes / follow-ups

- **Smartling** must have `string_format: icu` enabled for these files (config lives in the
  Smartling project — we control it). Non-`en` locales are regenerated by Smartling in ICU
  from the ICU source; they are converted here once for a consistent runtime cutover.
- `<Trans>` with tags **inside** a plural branch is not supported (ICU makes `<Trans>` parse
  every branch's tags). No such key exists; keep tags and plural in separate keys.
